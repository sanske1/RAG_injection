# 靶场失误与经验（自建，非上游原文）

> 本文件是**实战复盘**，来源是本地 CISP-PTE 靶场（`192.0.2.10`，端口 9081-9085）的实操记录，
> **不是上游权威文档原文**，与 `sources/` 下其余仓库性质不同，单独入 `pentest_lessons` 集合。

## 失误一：爆破过滤器按响应体大小过滤，把成功响应一起滤掉了

**事实**：用 ffuf 爆破后台登录，失败响应是 `200 / 1786 字节`，于是用 `-fs 1786` 过滤掉失败。
结果跑完 5 万词（rockyou 前 5 万）零命中。正确答案 `password123` 就在 rockyou **第 1384 行**，
早已跑过——**是被过滤器自己滤掉的**。成功响应是 `302 / 1786 字节`。

**根因**：**登录成功与失败的响应体大小完全相同，只有状态码不同**。按大小过滤时，
`302` 的成功响应与 `200` 的失败响应被同等对待，一起被滤除。

**正确做法**：
- 按**状态码**过滤，如 `-fc 200`（滤掉 200，保留 301/302 等）；
- 爆破前必须先确认**成功与失败究竟差在哪个维度**（状态码 / 响应体大小 / 关键字 / 跳转目标）。
  若无法制造一次成功样本，就同时保留状态码与大小两列对照着看，不要只筛一维。
- 推广到一切「响应对齐」的爆破（口令、认证、目录、参数）：**过滤条件是先验证出来的，不是猜出来的。**

## 失误二：把「只有 lo」误判成「没有网卡」

**事实**：采集环境信息时 `ip -4 -br addr` 只显示 `lo`，据此判断目标没有可用网络接口，
差点让用户去改虚拟机设置。过一会儿再看，`eth0` 已拿到 `192.0.2.20/24`。

**根因**：DHCP 尚未完成时就查询，把「暂时没有地址」当成了「配置有问题」。

**正确做法**：只显示 `lo` 时要用 `ip -br addr`（含 IPv6 链路本地地址）复核、
或隔几秒重查，再下结论。**环境断言必须在证据稳定后才出口。**

## 失误三：日志分析中把「响应体最大的请求」当成入侵信号

**事实**：一开始看到某个 IP 出现了 247KB / 153KB 的超大响应，误以为是后台页面被拉取（登录成功）。
实际那些只是 `jquery.js`(247KB)、`style.css`(51KB) 等**静态资源**，任何浏览器打开登录页都会加载。

**根因**：脱离了 URL 只看响应大小。

**正确做法**：判断「登录是否成功」要看**同一条 URL 的状态码变化**——
例如 `/admin/index.php` 在登录前返回 `302`（被踢回登录页）、登录后返回 `200`（拿到页面），
这种**同一路径的状态跳变**才是认证态切换的硬证据。

## 经验一：上传 WAF 的绕过——尾点文件名

**实测规则**（用对照实验逐一定位）：
- 扩展名 `.php` `.php5` `.phtml` `.pHp` `.PHP` `.txt` `.html` 一律拦截；
- 扩展名 `.png` `.gif` `.jpg` `.jpeg` 放行；
- 放行的同时**还要校验图片魔数**——纯文本内容但名叫 `.png` 的同样被拦，文件头写 `GIF89a` 即可通过。

**有效绕过**：文件名写成 **`shell.php.`（结尾一个点）**。
最后一段扩展名为空、不触发白名单检查，而 **Apache 会把 `shell.php.` 当 `shell.php` 执行**。

**实测无效的绕过**（别浪费时间）：
- `shell.php.gif` / `shell.php.jpg`：Apache 只按**最后一段**扩展名处理，会当图片原样返回源码，**不执行 PHP**；
- 靠改 POST 字段名指定保存名：无效；
- 文件名里塞路径穿越：服务端用 `basename()` 取掉了；
- 直接传 `.htaccess`：不在白名单，被拦。

**方法论**：**一次只改一个变量**（扩展名 / 魔数 / 字段名），对比响应差异，
才能区分「按扩展名拦」「按魔数拦」还是「两者都拦」。

## 经验二：命令注入 WAF 黑名单的定位与绕法

**实测黑名单**：`;` `&&` `||`、反引号、`$()`、`ls`、`cat`、`echo`、`*` 全部被处理掉。

**绕法**：
- 命令分隔符改用 **`|`**（未被拦）；
- 读文件避开 `cat`，用 `head -c 300 <file>`、`tac`、`grep .`、`nl`；
- 列目录避开 `ls`，用 `find <dir> -maxdepth 3`。

**判断技巧**：黑名单是**「删除」还是「拦截」**决定绕法。
本次是「整词删除」——发 `order by 1-- -` 回显成 `orderby1---`（空格被删、注释粘连），
据此改用 `/**/` 当空格、`#` 当注释即可。

## 经验三：SQL 注入 WAF 黑名单的绕法

- **空格被整删** → 用 MySQL 注释 `/**/` 代替空格；
- **注释被破坏**：`-- -`（井号空格）会被删成 `---` 而失效 → 改用 `#`（URL 中编码为 `%23`）；
- **关键词整词删除**（如 `union` 被删成空） → **双写还原**：写 `uniunionon`，被删掉一次后正好剩 `union`。
  前提是过滤器**只替换一次**。

**巨大优势**：该靶机把拼接后的 SQL **回显在页面上**。
每发一个 payload 都能看到「服务器实际构造出的语句」，WAF 改了什么一目了然——有回显就先看回显。

## 经验四：日志分析——区分扫描器噪声与真实攻击者

**扫描器（Acunetix）特征**：
- 请求 `/acunetix-wvs-test-for-some-inexistent-file`；
- 参数里带 `?name=acunetix_test`；
- UA 中塞入 `';print(md5(acunetix_wvs_security_test));$a='` 之类的测试串；
- 使用 `TRACE` / `TRACK` / `PROPFIND` 等非常规 HTTP 方法；
- 大量 `/etc/passwd` 目录穿越，但**状态码全是 400（全部失败）**。

**真实攻击者特征**：
- **定向**打单一入口（本例：1051 次 `POST /adminlogin.php`，其余端口路径只是字典扫过）；
- 工具痕迹：Referer 出现 `http://burp/show/1`（Burp Suite）；
- **状态码出现异常**：登录 POST 由连续的 `200` 变为**一次 `302`** = 口令爆破成功；
- 随后出现**认证态变化**：`/admin/index.php` 由 `302` 变 `200`。

**方法**：按 IP 统计**状态码分布**、按 URL 统计**请求密度**，
比单纯比「谁请求多」更能定位真凶——扫描器请求量通常最大，但一次都没成功。

## 经验五：先确认隔离边界，再谈「跨题利用」

多端口靶场未必是同一台机器。本例五个端口是**五个互相隔离的 Docker 容器**，
每个容器里只有自己的 `/app/cisp-pte/<端口后两位>/`，
**不能拿 A 题拿到的 RCE 去读 B 题的 key**。

**判断方法**（从已有 shell 内）：
- `ls -la /` 看有没有 `/.dockerenv`；
- `cat /proc/1/cgroup` 出现 `/docker/<id>` 即在容器内；
- `find / -name "<另一题的独有文件名>"` 直接验证能不能看到；
- `ls /app` 看有没有别的题目的目录。

**交叉验证很有必要**：我先是「按目录猜」以为 9084 能看到 9082，被实测否掉后才确定隔离。

## 经验六：拿凭据的优先级——先找泄漏，最后才爆破

**顺序**：
1. 日志与错误文件（`access.log` / `error.log` / `debug.log`）；
2. 源码备份（`*.bak` `*~` `*.swp` `*.phps` `*.save` `*.old`）；
3. 版本控制目录（`.git/config`、`.svn/entries`、`.hg/`）；
4. 配置文件与信息页（`config.php`、`phpinfo.php`）；
5. 框架已知默认口令；
6. SQL 注入读库（`mysql.user`、业务表）；
7. **最后才是爆破**。

**本例真正奏效的链路**：
- 用 SQL 注入 dump `mysql.user` → 拿到 MySQL root 哈希
  （MySQL 4.1+ 的哈希 = `*` + `sha1(sha1(password))` 的大写十六进制）；
- 本地算哈希跑字典（纯 CPU，比在线爆破快几个数量级）→ 得到密码；
- 目标还**暴露了 phpMyAdmin**，可借它在目标容器内执行 SQL：
  `SELECT LOAD_FILE('/path/to/source.php')` 读源码，
  或 `INTO OUTFILE` 写 webshell（需 `@@secure_file_priv` 为空）。

**要点**：同一镜像构建的多个容器，**MySQL 等内置服务的凭据通常是通用的**。
从任意一个容器拿到哈希即可破解出所有容器共用的口令。

## 经验七：静默失败也是信息

响应**完全不变**（字节级一致、md5 相同）说明请求没有进入业务逻辑，
或被前置规则（WAF / 代理 / 校验）拦下了——这本身就是定位规则边界的线索，
不要因为「没有报错」就略过。反之，**响应有变化时一定要先看变化在哪一维**
（状态码？大小？还是内容），再决定下一步。
