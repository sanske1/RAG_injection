# 交给其他 agent 的黑盒测试任务

这份测试是**黑盒**的：测试者**不看语料原文、不看任何答案文件**，
只向 RAG 提问、只看它返回什么、据此打分。

材料在 `测试/黑盒测试/`，按顺序读：

```
00-先读我.txt
01-任务说明.txt
02-测试步骤.txt
03-报告要求.txt
04-测试题.txt
05-测试题.txt
```

## 怎么交出去

对被测 agent 说这一句就够：

> 读 `测试/黑盒测试/00-先读我.txt`，按里面的顺序读完其余文件并执行。

## 为什么拆成多个小文件

某些 agent 的单次读取有大小限制，读大文件会失败，然后开始瞎猜。
（实测豆包的 agent 就卡在这里：它在 4000 字节边界反复字节切片，
切成多字节汉字中间导致解码失败，接着一路误判成"环境故障"。）

每个文件都在 4KB 以下，单独读即可。

## 三个测试分别测什么

| 测试 | 测什么 | 是否需标准答案 |
|---|---|---|
| 一 · 可用性打分 | 返回内容够不够照着做（0/1/2） | 不需要 |
| 二 · 措辞敏感性 | 纯中文 / 纯英文 / 中英混排，返回是否一致 | 不需要 |
| 三 · 点名来源 | 问题里点名某个仓库，返回来源对不对得上 | 不需要 |

三个测试**都不需要标准答案**——判定依据只有 `search_pentest_kb` 实际返回的内容，
以及 RAG 自己标注的来源。这就是它能做成黑盒的原因。

## 背景（给组织者看，不必给被测 agent 看）

被测系统是本地 RAG：语料切块后用 `bge-m3` 向量化，存进 Milvus 集合 `pentest_kb`，
工具 `search_pentest_kb` 由 MCP 提供。**它只做检索，不生成答案**。
所以"没返回相关内容"应归因到**检索**，而不是"没生成好答案"。

原有的「预置答案键自动判分」脚本路线已删除（那是白盒口径，参考意义有限）。
现在只有这一条黑盒路线。
